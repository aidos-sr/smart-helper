# Исправления надёжности AI — 25 ноября 2026

Изменения подготовлены для репозитория `aidos-sr/smart-helper`, исходный коммит `1071edda779e6977671e3c58a03653db8c4880aa`.
HTML, CSS, оформление и расположение элементов не изменены. Новые сообщения об обрыве и кнопка продолжения используют существующие стили.

## Что исправлено

- Прежний таймаут 18–24 секунды охватывал всю генерацию, поэтому сервер мог сам оборвать ещё работающую модель. Теперь ожидание первого текста и простоя ограничены отдельно, а общий бюджет включает авторизацию и поиск: 52 секунды для чата. Учебные модули используют отдельный бюджет 165 секунд при лимите функции Vercel 180 секунд.
- Поток завершается успешно только при явном подтверждении завершения. Конец TCP/HTTP-соединения и `[DONE]` без причины завершения не маскируют оборванный ответ.
- Резервная модель включается до первого видимого текста. После начала ответа другая модель не подмешивает свою версию решения. При разрыве текст остаётся на экране и в истории; его можно продолжить кнопкой «Жалғастыру».
- Лимит ответа увеличен с 2000 до 4000 токенов в обычном чате и до 6000 в глубоком. При `finish_reason=length` есть одна автоматическая попытка продолжения в оставшееся время; если её недостаточно, доступна ручная кнопка. Автоматическое продолжение входит в тот же запрос квоты; ручное — новый запрос. Дополнительная генерация в платном режиме расходует токены провайдера.
- История собирается с конца, сохраняя последний вопрос целиком: до 40 сообщений и 60 000 символов. Вопрос длиннее 12 000 символов получает понятную ошибку вместо скрытого обрезания.
- Текстовые вложения длиннее 20 000 символов отклоняются явно. Для старых фото/PDF модель получает предупреждение, что исходные файлы нужно прикрепить повторно; их содержимое по-прежнему не записывается в базу.
- Поток корректно разбирается при разделении UTF-8 и CRLF между пакетами. Сервер отправляет служебные keep-alive сообщения, отменяет запрос после отключения браузера; клиент ограничивает ожидание 65 секундами.
- Удалён недоступный резерв `dots-studio/dots-3-note-preview:free`. Учебные модули используют быстрые модели с совместимым `json_object` и схемой в инструкции. При ошибке поддержки формата есть переход к инструкции без `response_format`, при этом серверная проверка результата остаётся обязательной. Наличие моделей проверено через публичный каталог OpenRouter 25.11.2026; доступность может меняться.
- Планы, карточки и тесты проходят серверную проверку: точное число элементов, последовательность дней, обязательные поля, разные варианты ответа и допустимый индекс правильного ответа. Обрезанный JSON не выдаётся за успешный результат.
- Приветствия и простые вычисления не запускают ненужный поиск. arXiv/OpenAlex подключаются в чате для научных запросов; в глубоком веб-режиме используется поиск провайдера без дублирующего обращения к энциклопедиям. Возвращённые провайдером ссылки извлекаются из аннотаций.
- Инструкция модели требует отмечать неопределённость, исправлять ложные предпосылки, проверять вычисления и не заявлять о проверке фактов, если поиск не дал подтверждения. Это снижает риск выдумок, но не гарантирует фактическую точность любого ответа.
- Незавершённый ответ не начисляет XP и не превращается в тест/карточки. Повтор старого запроса после нового вопроса блокируется. При смене аккаунта текущий запрос отменяется, а переписка очищается из памяти интерфейса.

## Установка на Windows

1. Сохраните резервную копию вашей папки проекта, особенно если в ней есть неопубликованные изменения.
2. Распакуйте архив в отдельную папку. Папка `smart-helper` содержит полные исходники; `smart-helper-ai-fixes.patch` — только изменения к указанному выше коммиту.
3. Перенесите изменения в `C:\Users\Aidoxa\Documents\smart-helper-main`. Сохраните существующие `.env`, `.git` и настройки Vercel. Секретных ключей в архиве нет. Если локальный проект заметно отличается от указанного коммита, применяйте изменения с просмотром различий.
4. В PowerShell:

```powershell
cd "C:\Users\Aidoxa\Documents\smart-helper-main"
npm ci
npm test
npm run build
```

Для локального запуска с серверными функциями и вашим `.env`:

```powershell
npx vercel dev
```

Обычный `npm run dev` запускает только frontend: AI API требует Vercel Functions и серверных переменных.

Вариант применения патча в Git-проекте с подходящей версией исходников:

```powershell
git apply --check "ПУТЬ_К_АРХИВУ\smart-helper-ai-fixes.patch"
git apply "ПУТЬ_К_АРХИВУ\smart-helper-ai-fixes.patch"
```

После проверки сохраните изменения в Git и отправьте их в подключённую к Vercel ветку. Если автоматическая публикация выключена, создайте deployment в Vercel вручную. Прямая публикация требует подключения GitHub с правом записи; серверные секреты задаются отдельно в Vercel.

## Настройки Vercel

Существующие ключи OpenRouter и Supabase сохраняются. Проверьте пользовательские переопределения моделей: значения из Environment Variables имеют приоритет над кодом, поэтому обновление `.env.example` само по себе их не меняет.

Для изменённых маршрутов рекомендуются значения:

| Переменная | Значение |
| --- | --- |
| `OPENROUTER_FAST_MODEL` | `google/gemma-4-31b-it:free` |
| `OPENROUTER_FAST_FALLBACK_MODEL` | `google/gemma-4-26b-a4b-it:free` |
| `OPENROUTER_FAST_LAST_RESORT_MODEL` | `openrouter/free` |
| `OPENROUTER_STRUCTURED_MODEL` | `nvidia/nemotron-3.5-super-vl:free` |
| `OPENROUTER_STRUCTURED_FALLBACK_MODEL` | `inclusionai/ling-3.2-flash:free` |
| `OPENROUTER_STRUCTURED_LAST_RESORT_MODEL` | `openrouter/free` |

Можно удалить только эти переопределения моделей, чтобы использовались новые значения из кода. После изменения окружения нужен новый deployment. Обычный чат остаётся на бесплатных моделях; глубокий режим и его интернет-поиск могут тарифицироваться, как и раньше. API-ключи в переписку отправлять не нужно.

## Что проверено и что требует живого окружения

- Автоматические тесты покрывают SSE, таймауты, отмену, обрывы, резервирование, продолжение, контекст и валидацию, а также обработчик API с подставными OpenRouter/Supabase ответами. Внешние платные запросы тестами не выполняются.
- Production-сборка и проверка синтаксиса проходят.
- В браузере проверены сохранение частичного ответа, его продолжение в той же реплике, блокировка устаревшего повтора, выход из тестовой сессии и сохранность оформления. Для этого использовались временные локальные ответы API. Тестовая авторизация и подставные ответы в архив не включены.
- Реальная скорость, качество ответов на русском/казахском, работа с вашими документами и тарифные ограничения требуют проверки с вашим серверным API-ключом. Эти показатели не измерены, ключи не предоставлялись.

После публикации проверьте: короткий вопрос на казахском и русском; длинное решение; уточнение после длинной переписки; фото/PDF; временное отключение сети в середине ответа и «Жалғастыру»; генерацию 30-дневного плана и 15 вопросов теста.

## Дополнительное исправление учебных модулей

- Все шесть учебных действий (план, карточки, тест, сокращение, перевод, исправление) получают потоковые события прогресса и явное завершение. Общий таймаут клиента охватывает fetch, чтение ответа и обновление авторизации: 175 секунд для учебных задач.
- Планы строятся по 5 дней двумя параллельными запросами; вопросы теста — последовательными группами по 5, с передачей списка уже созданных вопросов. Валидация учитывает короткую последнюю группу. Квота списывается один раз за весь запуск.
- Длинные переводы и исправления обрабатываются частями с сохранением разделителей абзацев. Все части объединяются в исходном порядке. Слишком длинный вход отклоняется до обращения к модели и списания квоты.
- Широкий JSON-режим, явная схема, отключение необязательного reasoning, ограниченное исправление невалидного ответа и резерв модели заменяют несовместимые strict-запросы. Лимиты генерации и отмена чтения учитывают весь запрос.
- Долгое сохранение больше не блокирует кнопку генерации. Локальная копия доступна сразу; ожидание Supabase ограничено 8 секундами. Загрузка библиотеки ограничена 6 секундами и объединяет облачные записи с локальными, сохраняя свежий материал.
- Кнопка следующего вопроса скрыта до ответа; программный повтор перехода или ответа не начисляет повторные баллы.
- Проверка в браузере выполнялась с временными ответами OpenRouter и Supabase: полный 30-дневный план, тест 15/15, создание и перелистывание карточек, три инструмента, повторное открытие локального плана после перезагрузки при недоступном облаке. Временная авторизация и ответы не входят в исходники. Реальная задержка и содержательное качество модели зависят от производственного ключа и доступности провайдера; эти показатели тестовыми ответами не измеряются.

## Исправление ложного таймаута после получения ответа

Воспроизведён случай, когда полный корректный JSON и `finish_reason=stop` уже получены, но Promise отмены HTTP-потока не завершается. Ожидание `reader.cancel()` задерживало результат до таймаута. Теперь отмена выполняется без блокировки готового результата, переключения модели и обновления сессии. Серверная валидация JSON сохраняется.

Активность в `reasoning`/`reasoning_details` учитывается как работа провайдера, с сохранением общего ограничения времени; одни служебные keep-alive комментарии срок не продлевают. Модель, не ответившая вовремя, исключается до конца текущего учебного задания. Бесплатный резерв по умолчанию вынесен к другому провайдеру (Ling 3.2 Flash); явно заданные настройки имеют приоритет. В серверные логи добавлены модель, исход попытки, время и идентификатор запроса, без текста пользователя, ключей и содержимого reasoning. При резервном переходе интерфейс сообщает, что выполняется повторная попытка.

Этот случай воспроизводится тестами потока с зависшей отменой. Он не доказывает причину каждой ошибки конкретного пользователя: для проверки производственного таймаута нужна авторизованная сессия сайта либо серверные журналы этого запроса.
