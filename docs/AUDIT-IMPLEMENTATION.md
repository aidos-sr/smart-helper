# Выполнение аудита Smart Helper

Дата: 26 ноября 2026 года. База: `4165b06e9d7b372e2d1edf0f8376b9e822fa5060`.

**Статусы относятся к коду в ветке, а не к опубликованному сайту.** Production Supabase/Vercel/OpenRouter не изменялись. «Код» означает реализованный механизм, проверенный локально в указанном объёме; SQL-механизмы требуют применения миграции. «Частично» означает, что часть рекомендации ещё требует измерений, внешней настройки или отдельной реализации.

Из 94 пунктов: **79 — реализован механизм в коде, 15 — частично**. Ни один частичный пункт не объявляется закрытым.

Проверки: `npm run build` (включает синтаксис и 111 тестов), `npm audit` — 0 advisory в проверенном дереве. Тесты не обращаются к настоящим ученикам, рабочей базе или AI. PGlite исполняет PostgreSQL/PLpgSQL/RLS, а auth-пользователи созданы тестовой схемой. DOM-проверки работают через JSDOM; визуальные проверки настоящих браузеров не выполнены.

Сборка: основной JS около 74 КБ (gzip около 26 КБ), основной CSS около 38,5 КБ. SDK Supabase около 207 КБ и KaTeX JS/CSS загружаются отдельно по необходимости. Сравнение с аудитом 263/66,5 КБ описывает размер чанков, а не измеренную задержку на устройстве.

Порядок выпуска, ограничения и внешние действия: [DEPLOY-AUDIT.md](DEPLOY-AUDIT.md).

C01 — применить и проверить реальные RLS/миграции; C02–C04 — настройки Auth, паролей и redirects; C05–C06 — фактические лимиты/модели/цены/политики провайдеров; C07 — production-логи; C08 — регионы и задержки; C09 — резервное копирование/восстановление; C10 — защита main и права (поиск характерных форматов ключей по доступной истории Git не дал совпадений; это не доказательство отсутствия всех видов секретов); C11 — разделение staging/production; C12 — требования организации к школьным данным. Эти пункты не считаются выполненными только наличием кода.

Платный режим выключен по умолчанию. Бюджет приложения резервирует оценку; точную биллинговую стоимость и жёсткий лимит ключа обеспечивает провайдер. Проверка цитаты устанавливает её наличие в исходнике, а не истинность вывода модели. XP остаётся самооценкой учебной активности, не школьной отметкой.

## Дополнительная проверка перед выпуском

После подтверждения владельцем успешного выполнения SQL-миграции проверены изменения аккаунта при смене сессии. Экспорт, удаление аккаунта и смена пароля теперь используют заранее зафиксированный токен и владельца; сервер удаления проверяет expectedUserId. Смена пользователя до отправки отменяет запрос, после отправки не может перенаправить его на другой аккаунт. Дополнительные регрессии проверяют stale confirmation, A→B, A→выход→A и серверное отклонение несовпадающего владельца. Всего 111 локальных тестов прошли.

Владелец сообщил `Success. No rows returned` для миграции; независимая проверка production-схемы не выполнена. Vercel preview собирается, но HTTP-проверка перенаправлена на вход Vercel. Реальная проверка входа и работы учебного задания до объединения PR требует сессии владельца.

OAuth/recovery callback определяется до изменения маршрута, чтобы не удалить hash с токенами до обработки SDK. Начальная загрузка сессии не перезаписывает более новое auth-событие.
