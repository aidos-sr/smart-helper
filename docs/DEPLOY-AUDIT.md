# Выпуск исправлений аудита

Изменения подготовлены в отдельной ветке. Владелец подтвердил успешное выполнение третьей миграции сообщением `Success. No rows returned`. Самостоятельно состояние рабочей базы не проверялось; main и опубликованный сайт в этом проходе не обновлялись. Новая API-версия зависит от третьей миграции: без неё ограничения и задания возвращают 503, а прогресс остаётся локальным. Не выпускайте только frontend или только API без проверки совместимости.

1. Создайте отдельный staging Supabase и Vercel preview с отдельными ключами. Сделайте резервную копию рабочей БД и проверьте восстановление на staging.
2. Примените все три миграции по порядку. Для существующей базы достаточно `202611250001_audit_hardening.sql`. Она добавляет квоты хранения, события прогресса, задания и управляющие таблицы; прямые записи клиента в `progress` заменяются RPC. Проверьте реальные роли/политики, включая дополнительные политики из панели. При старых открытых вкладках до обновления страницы синхронизация прогресса старого клиента будет отклоняться; локальные значения не удаляются.
3. Задайте переменные из `.env.example`. `AI_PAID_ENABLED=false` — значение по умолчанию. Для платного режима нужны одновременно `AI_PAID_ENABLED=true` и UUID в `AI_PAID_USER_IDS`. Суммы бюджетов — USD в день, цена маршрута — USD за миллион токенов. Резервирование в приложении является консервативной оценкой, включая резерв на плагины; оно не заменяет фактический учёт провайдера или жёсткий лимит ключа OpenRouter. Сверьте цены плагинов и размер резерва с действующим тарифом до включения платного режима.
4. Выберите `AI_GLOBAL_ATTEMPTS_PER_DAY` по реальной общей квоте ключа. Счётчик учитывает входящие задания и внутренние обращения, включая неуспешные. Не считайте значение примера подтверждением ёмкости бесплатного аккаунта. Проверьте доступность всех настроенных моделей и совместимость `data_collection: deny`, `AI_REQUIRE_ZDR` и `AI_ALLOWED_PROVIDERS`.
5. В Supabase проверьте подтверждение email, политику паролей, защиту регистрации, rate limits и точный allowlist callback URL. Восстановление пароля использует origin сайта с `/#recovery`. Ограничьте список production/preview адресов; не добавляйте бесконтрольные wildcard.
6. В Vercel задайте WAF/rate limit перед авторизацией, допустимые размеры запроса, близкие к БД регионы и алерты по ошибкам. Файлы PDF проверяются в worker thread; обязательно проверьте включение `lib/pdf-inspect-worker.js` в пакет функции на preview.
7. Прогоните `npm ci`, `npm run build`, `npm audit`, затем staging-сценарии ниже. Workflow `Verify / verify` должен стать обязательной проверкой ветки main в GitHub Settings. Настройка branch protection не менялась автоматически.
8. Проверьте глазами Chrome/Edge/Firefox/Safari и школьные iOS/Android: клавиатуру, поворот, фокус, контраст, reduced motion, печать и формулы в экспорте. В этом проходе выполнены DOM-интеграции, а доступ к живому локальному браузерному предпросмотру был недоступен. Такие проверки не считаются выполненными.
9. Пройдите эталонный набор `tests/fixtures/learning-eval.json` на реальных моделях без production-данных. Сохраните точность, язык, TTFT, полное время и стоимость. Ответы с цитатами требуют проверки соответствия цитаты выводу; наличие фрагмента само по себе не доказывает правильность.
10. Согласуйте операторские сведения и текст `public/terms.html`. Для школьных данных отдельно подтвердите допустимых получателей и требования организации. После успешных проверок объедините PR и выпустите новую версию, затем выполните безопасный smoke.

## Ограниченные staging-сценарии

- A → выход → B во время чата, теста, карточек, плана, загрузки истории и подготовки вложения: текст A не должен появиться или сохраниться в B. Повторите A → выход → A.
- Отключите облачное сохранение. Создайте более 30 материалов, восстановите сеть: исходные ID и pending-копии сохраняются, повторная синхронизация не создаёт дубликатов. Заполните localStorage: материал остаётся на экране, а невозможность долговременного сохранения явно видна.
- Отключите сеть во время генерации после первого блока. Обновите страницу, войдите тем же пользователем, используйте «Аяқталмаған тапсырманы жалғастыру». Готовые блоки не должны генерироваться повторно. Задания имеют срок 7 дней, активная аренда — 180 секунд, по умолчанию один активный job на пользователя и 10 на проект.
- Два устройства добавляют XP одновременно. Повторите доставку одного события: XP не должен пропасть или удвоиться. Не используйте XP как школьную оценку.
- Подмените провайдера ограниченной заглушкой: 429, 422, пустой поток, EOF, `finish_reason=length`, зависшая отмена. После ошибки дневная учебная квота может вернуться, счётчики попыток остаются.
- Исчерпайте тестовый финансовый резерв и лимит проекта; никаких реальных нагрузочных атак или значимых трат не нужно. Проверьте отклонение и код запроса в UI/логах.
- Остановите генерацию. Частичный тест не должен показывать ложное завершение, а готовые вопросы должны оставаться доступными.
- Экспортируйте тест отдельно для ученика и с ключами. Проверьте русский/казахский, формулы, переносы, печать. Для форматированного экспорта используйте печать в PDF; TXT сохраняет формулы как исходную запись, JSON сохраняет полную структуру.

## Наблюдение и восстановление

Сервер пишет `AI request metric` с requestId, task, elapsedMs, authMs/quotaMs/searchMs и TTFT, когда эти этапы выполнялись. Текст ученика в эти записи не входит. Для агрегирования экспортированных логов: `npm run metrics:summary -- path/to/log.txt`. Внешний приём метрик, Web Vitals, алерты по расходам и упражнения восстановления требуют настройки оператора; они не объявляются подключёнными.

Истёкшие задания удаляются при следующем резервировании. Для базы без новых запросов оператор может добавить ежедневную задачу `delete from public.ai_jobs where expires_at < now()` от server role. Облачные материалы не удаляются автоматически по возрасту; действуют предел 500 чатов/материалов и 20 МБ на владельца, пользовательское удаление и полный экспорт. Единственные pending-копии на устройстве автоматически не вытесняются.

При сбое после выпуска сначала отключите платный режим и новые запросы, сохраните логи по кодам ошибок, исправьте конфигурацию или выпустите совместимую версию API. Не удаляйте новые таблицы с заданиями и очередями ради отката frontend. Возврат старых прав прямой записи прогресса возвращает прежний риск потери изменений и требует отдельного решения оператора.
